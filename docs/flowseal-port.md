# Android-порт основного сценария Flowseal, 1.9.0

Сверка выполнена 2026-10-23 с
[Flowseal/tg-ws-proxy @ 307a384ab7f522e34bb1a045884d0bd90f40bee5](https://github.com/Flowseal/tg-ws-proxy/tree/307a384ab7f522e34bb1a045884d0bd90f40bee5).
Исходники используются по MIT, уведомления включены в APK.

## Что перенесено и сохранено

| Часть | Flowseal | Android 1.9.0 |
|---|---|---|
| Локальный вход | MTProto, 127.0.0.1:1443 | То же; секрет отдельный для установки |
| Выбор DC | Из obfuscated handshake | То же, включая media DC |
| Передача | AES-CTR transport re-encryption, MTProto frames over WSS | Нативный Kotlin/Java, без Python/Docker |
| Маршруты | Telegram WSS, CF, TCP и дополнительные транспорты | Telegram WSS → CF WSS → TCP |
| Окончание WSS-сессии | EOF, ошибка, отмена | То же; без эвристик «на эти байты должен быть ответ» |
| Пул | Проверка EOF, ротация, backoff | Отключён: у имеющегося Android-пула нет наблюдения за EOF |
| Фоновая работа | Desktop-процесс | Foreground service, уведомление, wakelock, плитка |
| Смена сети / пробуждение | Зависит от desktop-платформы | Сохранены Android callbacks и восстановление после сна |
| Дополнительные возможности | HTTP/2 media, Workers, Fake TLS, PROXY protocol | Не перенесены в этой версии |

Это порт базового локального сценария, не полная копия desktop-продукта.
Публичные CF-домены остаются сторонней инфраструктурой. При недоступности
всех маршрутов приложение не сможет обеспечить связь само по себе.

## Воспроизведённые дефекты старой реализации

1. `BridgeSessionTest` передаёт в настоящий мост два исходящих transport-пакета
   после первого downstream-ответа. Соединение остаётся открытым, сетевых ошибок
   нет. Через 20 секунд старый CF-watchdog сам закрывает поток.
   Тест завершился ошибкой `Healthy opaque stream was closed by a response heuristic`.
   Прокси не видит смысл зашифрованных пакетов и не может решать, требуют ли они ответа.
2. `RawWebSocketLifecycleTest`: после EOF и WebSocket Close флаг `closed` уже
   выставлен, поэтому старый `close()` пропускает освобождение TLS-сокета.
   Оба теста провалились на старом коде и проходят после исправления.
3. Третий тест удерживает блокировку записи и вызывает `close()` из другого потока.
   Старое закрытие ждёт эту блокировку, что мешает восстановлению зависшего соединения.
   Теперь остановка закрывает сокет без отправки WebSocket Close под writer lock.

Эти тесты доказывают ошибки реализации; они не доказывают единственную причину
всех прошлых отключений на телефоне. Прежняя запись `stalled=false` показывала
только отсутствие срабатывания watchdog, а не причину завершения сеанса.
Новые записи `session_completed` содержат причину: client/upstream EOF,
класс I/O-ошибки или отмену, без содержимого сообщений и секрета.

## Дополнительные изменения

- Удалены watchdog, закрытие сессии после пяти минут без downstream и связанные
  с этими эвристиками блокировки целого маршрута.
- Сохранён cooldown домена при HTTP-ошибках установления WSS.
- Cooldown direct IP после connect timeout уменьшен с часа до 30 секунд.
- Изменение Android VALIDATED на прежней сети больше не сбрасывает соединения.
- Сохранены существующие секрет, порт и отметка успешной настройки Telegram.
- Неуспешный TCP connect теперь закрывает свой сокет.

Компромиссы: соединение по запросу требует нового TCP/TLS handshake; при сетевой
«чёрной дыре» без EOF обнаружение зависания остаётся за Telegram/TCP. Восстановление
после реальной смены сети и сна по-прежнему пересоздаёт соединения.

## Проверки

```sh
JAVA_HOME=/path/to/jdk17 ./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleRelease
```

- 29 тестов прошли после исправления; lint: 0 ошибок, 8 предупреждений.
- Отдельный дополнительный `BridgeTcpTest` прошёл: несколько обменов через реальные
  локальные TCP-сокеты, непрерывность AES-CTR в обе стороны и отмена блокирующих reads.
- Подписанный release APK успешно собран, его сертификат совпадает с APK 1.8.5.
- Тест с паузой 22 секунды проходит: поток остаётся открыт, затем корректно
  завершается по upstream EOF.
- Длительная проверка новой версии в Telegram на телефоне пока не выполнена:
  устройство доступно по ADB, но экран заблокирован.
- `adb install -r` передал APK системному установщику, который открыл
  `android.content.pm.action.CONFIRM_INSTALL`. Установка ожидает подтверждения
  на телефоне; на момент сборки установленной оставалась 1.8.5.

Последующая проверка после установки пользователем подтвердила 1.9.0 на
телефоне. Передача данных и восстановление listener после сна работают,
но повторное «Подключение прокси…» воспроизведено. Стабильность не подтверждена.
Локальный отчёт диагностики телефона не включён в репозиторий.
